**Zotero Research Database**

> 从收藏论文，到看清研究脉络。

在 Zotero 里，把论文全文、关键图表和你的阅读问题放进同一张表格。用自己的问题定义研究字段，让 AI 辅助填充，再由你核对、修改、比较和积累。

**文献继续留在 Zotero，阅读成果成为你自己的研究数据库。**

[下载 XPI](https://github.com/anzhaohao/zotero-research-database/releases/latest/download/zotero-research-database.xpi) · [更新记录](https://github.com/anzhaohao/zotero-research-database/releases) · [反馈问题](https://github.com/anzhaohao/zotero-research-database/issues)

支持 **Zotero 9.0.6–10.x** · 研究数据本机保存 · 可连接 API 或本机 CLI · AGPL-3.0-or-later

# 它能帮你做什么？

## 带着自己的问题读论文

收藏了几十篇相关论文，却很难说清各自解决了什么、差别在哪里？把这些问题直接变成表格列：

| 阅读字段示例 | 你希望从论文中得到的答案                   |
| ------------ | ------------------------------------------ |
| 论文定位     | 这篇研究的主要贡献是什么？一句话如何概括？ |
| 研究背景     | 要解决什么问题？已有研究卡在哪里？         |
| 核心思路     | 作者为什么这样做？关键假设和逻辑是什么？   |
| 研究实现     | 方案如何落实？哪些步骤和条件最关键？       |
| 结果证据     | 结论由哪些实验、图表或数据支撑？           |
| 局限与借鉴   | 哪些条件下有效？什么可以迁移到自己的研究？ |

这些只是示例。每个自定义字段只需填写**标题和给 AI 的提示词**，就能形成适合自己学科、课题和阅读习惯的方案。

## 让 AI 做初读，让你掌握最终判断

- **填充当前论文或批量处理**：根据字段提示词提取内容，逐字段显示处理状态并保存结果。
- **保留人工判断**：手动编辑后自动锁定，批量填充会跳过锁定值；需要重做时，用单元格的“重新生成”明确覆盖。
- **随时核对原文**：PDF 预览与研究内容并排，双击普通单元格可打开主 PDF；图表支持回到 PDF 对应页码或区域。
- **结果方便继续使用**：单元格支持编辑、复制和重新生成，内容可显示 Markdown、公式、段落与重点标记。字体、正文和标题字号可调整。

插件优先使用 MinerU Markdown，缺失时尝试 Zotero 已提取的全文；API、Ollama、Codex 等填充方式在没有可用全文时会提示先解析或 OCR。**全文不会自动截断**：超过 200,000 字符时会停止并提示拆分。AI 输出仍需对照原文核实，耗时与质量取决于全文长度、字段数量和模型服务。

## 把图表也放进阅读视野

预览列展示 PDF 页面缩略图，论文图表列展示解析得到的图片。无需反复在多个窗口之间切换，就能把“作者怎么说”和“图中证明了什么”放在一起看。

MinerU 支持**官方网页 API**和 **Docker / 自托管 API**；已有产物可优先复用，避免对同一 PDF 重复解析。还可选用 Zotero Figure 的已有本机结果。

## 横向比较，逐步形成自己的判断

表格跟随当前 Zotero 集合、保存搜索、标签与搜索范围。你可以筛选、排序、分组、拖动表头排序、调整列宽与行高，保存适合不同课题的视图。

需要汇总时，可建立动态比较或固定快照，调用 AI 辅助生成综合结论，并导出 **CSV、XLSX、HTML**，或通过系统打印保存为 **PDF**。

# 五步开始

1. **安装插件**：下载上方 XPI，在 Zotero 的“工具 → 附加组件”中打开齿轮菜单，选择“Install Add-on From File…”安装；按提示重启。
2. **切换表格**：选择个人库中的集合，点击文献工具栏上的表格图标。再次点击可回到 Zotero 默认列表。
3. **设置阅读字段**：进入插件设置的“字段”页，填写自定义标题和提示词。四个原生列为“预览、标题、基础信息、论文图表”，所有列均可控制显隐。
4. **连接一个 AI 助手**：在“外部 Agent”设置中配置 API 或本机 CLI，选择模型后点击“检查助手”。有需要时，先从“字段与工具”运行 MinerU 获取全文和图表。
5. **先读一篇，再批量处理**：运行填充，对照 PDF 核对结果，调整提示词；满意后再处理更多论文。

没有配置 AI，也可以使用表格、PDF 预览、手动填写字段和导出。**MinerU、Docker 与其他 Zotero 插件均按需使用，无需全部安装。**

# 选择你习惯的 AI 连接方式

| 连接方式        | 适合谁                          | 需要准备                                                    |
| --------------- | ------------------------------- | ----------------------------------------------------------- |
| OpenAI 兼容 API | 希望直接配置模型服务            | 服务地址、API Key、模型；支持 Responses 和 Chat Completions |
| Codex CLI       | 已安装并登录 Codex 的用户       | 本机可执行程序，沿用 CLI 的登录与供应商配置                 |
| Claude Code     | 已安装并登录 Claude Code 的用户 | 本机可执行程序及可用的模型配置                              |
| Ollama          | 希望使用本机模型                | 已运行的 Ollama 服务和已下载模型                            |
| 其他本机 CLI    | 已有自己的非交互模型工具        | 可执行程序、参数，以及兼容的 JSON 输出                      |

可以保存并切换多个供应商配置。模型、思考强度和**模型并发数（1–8）**会随对应配置恢复；强度是否生效取决于上游模型是否支持。提高并发可减少字段等待时间，也会增加服务压力与限流风险。

本机 CLI 可自动查找 **Codex / Claude Code**，也可手动添加程序路径；保存后出现在“助手类型”中。各连接方式均提供“拉取上游模型”，上游不支持枚举时可手动填写。Claude Code 仅有 OAuth 登录且无模型枚举凭据时，也可能需要手填。

“检查助手”用于验证连接和结构化响应，不读取论文、不写研究内容。填充失败时可查看错误提示中的具体原因；保存了路径并不代表模型服务已可用。

<details>
<summary>本机 CLI 配置与换机说明</summary>

- 在“设置 → 外部 Agent → 本机 CLI”中添加或编辑，填写名称、调用方式、程序位置与参数，点击“保存到助手”。可使用“自动查找 Codex / Claude Code”或“选择程序”。
- 换电脑后，先安装并登录对应 CLI，再重新查找或选择路径。插件不迁移 CLI 登录状态，也不代为安装模型工具或本机代理服务。
- Windows 的 `.cmd` / `.ps1` 启动器不能直接当作原生可执行程序运行。脚本型 CLI 可填写 Node / Python 等解释器路径，并把脚本路径放入启动参数。
- “其他 CLI · 提示词模式”默认通过标准输入传入提示词与 JSON Schema，也支持 `{prompt}`、`{model}`、`{effort}`、`{schema}` 参数占位符；完整论文建议通过标准输入传递。
- “其他 CLI · JSON 协议”通过标准输入接收包含 `task`、`prompt`、`schema` 等字段的 JSON，标准输出返回结果 JSON。连接检查的 `probe` 请求应返回 `{"ok":true}`。
- 自定义 CLI 必须支持非交互调用和兼容的结构化输出。只有交互式界面的工具需要额外适配；插件直接启动程序，参数不经过 Shell 执行。

</details>

# 已有 MinerU 结果？尽量不重复解析

- **共享产物目录**：Research Database 与 Bilingual Reader 可配置同一个 MinerU 产物目录，按 PDF 内容哈希复用 Markdown 和图片。
- **复用 llm-for-zotero**：开启对应选项后，转换前先查找已有缓存；找到可用结果时，复制进本插件目录，没有结果再正常调用 MinerU。
- **保留已有结果**：重新解析时先暂存和校验，再替换共享产物；失败时回滚旧结果。新图片使用内容哈希命名，并同步更新 Markdown 引用。
- **转换不挡住阅读**：处理窗口可移动、缩放，显示队列与成功、失败、取消情况。取消在安全阶段生效，已进入 Zotero 导入的任务会等待该阶段完成。

解析结果会关联到对应 Zotero 条目，并用于全文填充和图表展示。设置可隐藏原生列表中由插件标记的 MinerU 产物附件，让列表保持简洁；取消隐藏即可恢复显示。

<details>
<summary>Docker / 自托管接入说明</summary>

插件兼容 MinerU 4.x 与 3.x 接口，可配置本机或私有局域网服务地址。Docker 不是必需项；使用官方网页 API 时无需安装。

如需插件自动启动本机服务，请设置 Docker CLI、Docker Desktop 和包含 `compose.yaml` 的项目目录。自动启动使用以下固定命令，要求镜像已准备好，且 Compose 中存在对应的 profile 与服务：

```powershell
docker compose --profile api up -d --no-build mineru-api
```

自动启动只用于本机回环地址；其他部署由你自行管理。网页 API Token 与自托管地址分别配置，不能相互替代。

</details>

# 数据属于你，也需要分清备份范围

**论文书目与 PDF 由 Zotero 管理，研究字段与视图由本插件保存。** 插件读取原生标题、作者、DOI 等信息，不另建一套书目副本，也不直接修改 `zotero.sqlite`。

| 内容                                           | 保存与迁移方式                                       |
| ---------------------------------------------- | ---------------------------------------------------- |
| 书目、PDF 和 Zotero 存储型附件                 | 继续由 Zotero 管理，按其同步与备份设置处理           |
| 研究字段、已填内容、锁定状态、视图、比较与快照 | 保存在研究数据库目录的 `database.json` 等本机文件中  |
| 可迁移的插件设置                               | 保存在研究数据库目录的 `settings.json` 中            |
| MinerU 共享产物                                | 位于设置中指定的共享目录；未另设时跟随研究数据库目录 |
| API Key、MinerU Token、CLI 登录状态            | 留在本机凭据或对应工具中，需要在新电脑重新配置       |

建议在设置中选择明确的**研究数据库目录**，正常关闭 Zotero 后备份整个文件夹；如果 MinerU 共享目录另设，也要一并备份。没有指定目录时，使用 Zotero Profile 下的 `zotero-research-database` 文件夹。

更换研究数据库目录后，保存并重启可执行迁移：复制、校验成功后切换，源目录保留；目标冲突或校验失败时会提示原因。换电脑仍需迁移或同步对应的 Zotero 文献库，并重新确认程序路径与凭据，单独复制插件数据目录不能替代 Zotero 备份。

**研究字段不会随 Zotero 云同步，也不会自动出现在手机端。** 删除自定义字段采用可恢复归档，历史值保留；隐藏字段只影响显示，未归档的字段仍参与 AI 填充。

使用远程 API 或配置了远程供应商的 CLI 时，填充任务会向对应服务发送论文文本和提示词；使用 MinerU 官方网页 API 时会上传 PDF。调用边界由你选择的服务决定，插件的本机存储不代表模型推理也在本机完成。

# 使用前了解这些边界

- 当前面向**个人库中的普通文献条目**，群组库不在支持范围。
- 扫描件需要先获得可用的 OCR / 解析文本；不保证任意模型都能直接读取 PDF。
- 全文不等于结论必然准确。重要判断、数值、图表与出处请回到原文核对。
- 大集合首次打开、长论文和大量字段仍可能较慢；建议先用少量文献校准字段、模型和并发。
- 外文标题翻译优先复用 Translate for Zotero 的公共接口，失败时回退当前 AI 助手；译文保存到插件研究字段，原始标题保留。
