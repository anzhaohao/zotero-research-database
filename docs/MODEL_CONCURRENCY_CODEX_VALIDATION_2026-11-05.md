# 模型并发与 Codex CLI 实测（0.3.41）

本记录覆盖 2026 年 11 月 5 日上午的实现与验证；不把前一次 API 成功当成 CLI 成功，不把某模型失败推广到所有模型。

## 实现

- 设置 → 外部 Agent → 当前模型并发数：1–8，表示同一次文献填充同时生成的研究字段数。
- 并发值保存在供应商自己的模型配置表中，键由助手类型和模型 ID 组成；切换模型、切换供应商、保存后关闭重开均恢复对应值。
- 旧配置不要求迁移：API 默认 3，CLI 和其他适配器默认 1。新配置写入时验证整数和范围。
- 所有生产适配器通过统一调度器按字段发送完整论文；每个字段完成、校验后立即保存，保存回调串行执行。不会截断全文，也没有调用外部子代理。
- 取消、保存失败、认证错误、服务不可用、限流或超时会停止后续排队请求；已经保存的字段保留。已发出的请求仍按各自的取消或超时机制结束。
- Codex 自定义供应商在临时 worker 配置中的 HTTP/流重试次数设为 0。保留原认证、供应商路由、模型和思考强度，不修改用户原始 config.toml。上游短暂故障需要用户重试，避免 CLI 默认多轮重连拖长失败等待。
- 字段并发范围是单次文献任务；没有新增跨所有窗口、实例的全局配额器。比较任务和单字段刷新本身各是一条模型请求。

## CLI 正向闭环

使用生产 createAgentBridge、ExternalAgentExtractionService 和 ResearchRepository，在隔离 Zotero 10.0.7 profile 内读取真实 MinerU 全文和用户当前六个研究字段提示词。测试条目创建在隔离库，测试结束删除；不覆盖正式研究库或用户默认模型。

输入完整文本 37,223 字符，六字段均非空，逐字段事件与持久化快照一致。

| 模型 / 强度          | 字段并发 | 首字段保存 | 全部保存   |
| -------------------- | -------- | ---------- | ---------- |
| gpt-6.1-sol / max    | 2        | 25.694 秒  | 239.051 秒 |
| gpt-6.1-sol / medium | 3        | 11.202 秒  | 33.397 秒  |

两次同时改变了强度与并发，不能分别量化各参数的贡献；单次计时也不是稳定 SLA。medium / 3 已在本机完成真实六字段生成与保存，不保证其他上游同速。

质量检查包括：定位字段对方案性质与核心动作的一句话概括；空气实验约 220–470 nm 与另一组 220 mbar 氮气实验的区分；1.8 mJ / 0.5 mJ 条件与 2000 发累积光谱的边界。自动断言关键波段，人工核对上述信息与源文对应段落；没有把它描述为全文逐句审校。

另一个极短 JSON 请求通过相同生产 CLI 参数，在 gpt-6.1-sol / max 下约 7.7 秒成功。这不是全文速度指标。

## k3.1-pro 故障的严格分层对照

模型 k3.1-pro、强度 max、提示词、JSON schema、stream/store 参数完全一致。直连与网关使用该通道唯一未吊销的池凭据；完整 router 请求使用 router 认证，再由同一通道池选择上游凭据。没有输出或提交任何密钥。

| 路径                      | 结果               | 用时     | 请求 ID                              |
| ------------------------- | ------------------ | -------- | ------------------------------------ |
| 直连供应商                | HTTP 503           | 0.348 秒 | 7456d374-1f22-487c-a2d3-29710b63cf9e |
| 本地清洗网关              | HTTP 503           | 5.783 秒 | 35e13f9a-b42d-4225-b938-beda4da004c5 |
| 完整 router               | HTTP 503           | 5.890 秒 | 860d70ee-b551-45cd-9d63-f5fd4fcd72ad |
| 实际 Codex CLI，经 router | HTTP 503，退出码 1 | 8.382 秒 | e6dfc5cb-4207-4aaf-995e-a501465d318d |

前三条是相同最小请求的 HTTP 分层对照，第四条是 CLI 自己构造请求的独立验证，不能声称四者请求体逐字相同。直连已经返回同类错误，说明此次故障不依赖插件、网关或 router 才出现；没有修改供应商服务，k3.1-pro 仍不可用，也没有静默换模型。
