# 故障与修复

旧方式一次要求七字段完整输出，真实请求在约 86 秒时被上游中断，已有约 3,249 字符仍无法组成完整结果。非流式等待和整篇最后才保存，让用户持续等待后看不到任何内容。

新方式按字段发起普通 API 请求，最多三个同时进行；每个请求均携带完整全文。字段通过结构校验后立即保存并刷新表格，后续字段失败不会丢掉已有结果。“重试失败”只请求尚未完成的字段。这里没有启动外部 CLI 子代理，也没有给模型额外文件或工具权限。代价是全文随各字段重复发送，输入用量可能高于原先一次请求。

Responses 和 Chat Completions 均支持增量读取。收到协议终止标记后才接受结果；中途断流、超时、取消和截断均不能把半成品写入。插件尊重用户选择的协议、模型和思考强度，不自动换协议或降强度。正常论文默认保留全文；超过 200,000 字符时明确停止，不静默抽取片段。

无 MinerU 原文时，先检查 Zotero PDF 缓存是否完整索引；部分索引会要求完整重建，重建后仍不完整则不发送缓存片段。没有完整可读文本的扫描 PDF 在 API/Ollama/隔离 Codex 模式会停止并提示先做 MinerU 或 OCR。Codex 文献任务没有开放读取 PDF 的工具，不能假定它收到路径就读过全文。
